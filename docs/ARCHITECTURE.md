# 架构与恢复

SwiftUI 菜单栏只读取状态，串行后台队列执行系统命令和控制 API 请求。网络变化、定时检查和唤醒事件触发重新检测；进程存在不能单独证明 VPN 已连接。

## 配置生命周期

1. 未填写域名和 DNS 时显示“待配置”，不发送网络探测，也不创建协同租约。
2. 开启时验证设置，处理上一次遗留租约，并安装普通用户权限的恢复守护。
3. 从所选客户端最终生成的配置读取基线。验证 TUN、规则模式、公司 DNS 的实际 utun 路由和探测主机路由。
4. 首次修改前备份基线，通过控制 API 应用临时覆盖。DNS 仅指向绑定 VPN 接口的公司上游；添加 fake-IP 排除和域名 DIRECT，VPN 网段使用绑定接口的出口。
5. 独立查询最终生效的规则和 DNS 结果。配置、网卡或路由变化时重新生成覆盖，不切换 TUN。
6. 关闭模式、退出、休眠或 VPN 不可用时恢复最新配置源。只在本应用标记仍存在时恢复；客户端已替换覆盖时不再重写。

## 崩溃恢复

运行时标记与租约一起标识所有权。租约包括进程、应用路径和心跳，普通用户 LaunchAgent 每三秒检查一次。进程退出、应用被删除、心跳超过 45 秒或时钟明显回拨都会触发恢复。独立恢复程序位于用户状态目录，删除 app 不会一同删除它。控制 API 暂时不可用时持续重试；不会为恢复而启动或重启代理客户端。

客户端的正常启动不依赖 EasyClash；临时覆盖未写入它的配置源。恢复守护和 app 用文件锁协调，配置变更写入前检查源文件是否变化。CLI 提供显式恢复与卸载命令。

## 安全边界

- 不启动 root 服务，不写系统路由，不启动 DNS 监听器。
- FlClash 仅连接回环控制端口，核对监听进程归属，并在写请求前复核。
- API 凭据和配置通过标准输入传给 curl，不置于命令行参数或日志。
- 日志只记录固定事件代号；状态目录权限 0700，文件 0600。
- 备份和设置可能含有敏感信息，权限保护不等于脱敏，不应上传。
- 诊断复制文本以“目标 1”代替主机名，不输出 IP、配置正文或订阅。

对于只存在于运行时 API、未写入生成配置的修改，恢复并非完整三方合并；不要同时用其他工具改写 DNS/规则。未来扩展 VPN 支持前需要针对其路由和 DNS 行为单独验收。
